# G4.Abstraction.Logging

**G4.Abstraction.Logging** is a small structured logger for G4™ applications. It implements `Microsoft.Extensions.Logging.ILogger`, writes each entry to a daily log file through a .NET trace listener, and raises events before and after each entry is created. It targets `net10.0` and is marked as unsupported in browser environments.

## Installation

```bash
dotnet add package G4.Abstraction.Logging
```

## Use the logger

### 1. Create a logger

The second argument is a function, so the logger can read fresh settings later.

```csharp
using G4.Abstraction.Logging;

using Microsoft.Extensions.Logging;

var settings = new G4LoggerSettings
{
    G4Logger = new G4LoggerSettings.G4LoggerSettingsModel
    {
        OutputDirectory = "./logs",
        Type = "Json"
    },
    LogLevel = new Dictionary<string, LogLevel>(StringComparer.OrdinalIgnoreCase)
    {
        ["Default"] = LogLevel.Information
    }
};

var g4Logger = new G4Logger("Demo", () => settings);
```

The constructor creates the output directory and opens one file per logger name and UTC day, called `<name>.<yyyyMMdd>.log`. A name that already has a trace listener is not opened a second time. Source: `G4Logger.cs:69-78, 351-390`.

### 2. Write entries

The standard methods such as `LogInformation` and `LogError(exception, message)` are extension methods on `ILogger`. `G4Logger` also declares an event called `LogError`, so call the methods through an `ILogger` variable.

```csharp
ILogger logger = g4Logger;

logger.LogInformation("Application started.");
logger.LogWarning("This is a warning.");
logger.LogError(new InvalidOperationException("An error occurred."), "The operation failed.");
```

### 3. Choose the entry format

`Type` is compared without regard to case. Source: `G4Logger.cs:131-137`.

| `Type` | Entry |
| --- | --- |
| `Text` (default) | A readable block with a level code, the time, and one indented line per field. Exceptions are appended. |
| `Json` | One JSON object per entry with camel-case names: `logger`, `logLevel`, `timeStamp`, `machineName`, `message`, `exception`. |
| `Simple` | One line: UTC time, a three-letter level code, and the state. |
| `Xml` | Not implemented. The entry text is a message that tells you to use `Json`, `Text` or `Simple`. |

An entry is written as a trace warning for `Warning`, a trace error for `Error` and `Critical`, and a trace information line for everything else. Source: `G4Logger.cs:434-455`.

### 4. Choose which levels are written

The rule is in `ConfirmLogLevel` (`G4Logger.cs:204`). A level is written when one of these is true:

- It is `Information` or higher.
- It equals the level configured for the logger name.
- It equals the level configured under `Default`.

`None` is never written. Because the comparison is an exact match for the lower levels, setting `Default` to `Debug` lets `Debug` entries through, but `Trace` entries stay out unless `Trace` is the configured level.

If `EventId` in the settings is not zero, only entries with that event id are written. Source: `G4Logger.cs:108`.

### 5. React to entries with events

| Event | Argument | When |
| --- | --- | --- |
| `LogCreating` | `IDictionary<string, object>` | Before the entry is formatted. You can add or change fields. |
| `LogCreated` | `IDictionary<string, object>` | After the entry is written. |
| `LogError` | `Exception` | When writing an entry throws. The exception is not rethrown. |

Source: `G4Logger.cs:50-60, 144-170`.

```csharp
g4Logger.LogCreating += (sender, entry) => entry["Build"] = "2026.11";
g4Logger.LogCreated += (sender, entry) => Console.WriteLine($"Written: {entry["Message"]}");
g4Logger.LogError += (sender, exception) => Console.WriteLine($"Logging failed: {exception.Message}");
```

### 6. Register with dependency injection

```csharp
using G4.Abstraction.Logging;

using Microsoft.Extensions.Logging;

var factory = LoggerFactory.Create(builder => builder.AddG4Logger(settings =>
{
    settings.G4Logger.Type = "Json";
    settings.G4Logger.OutputDirectory = "./logs";
}));

var logger = factory.CreateLogger("Demo");
```

`AddG4Logger()` with no argument registers the provider only. The overload with an action also configures `G4LoggerSettings`. Source: `G4LoggerExtensions.cs:23-45`.

## Settings from appsettings.json

`new G4LoggerSettings()` reads the `Logging` section of `appsettings.json` in the current directory, then environment variables. It uses four values: `LogLevel`, `G4Logger:AddConsole`, `G4Logger:AddDebug` and `G4Logger:OutputDirectory`. An output directory of `.` or an empty value keeps the default, which is the current directory. Source: `G4LoggerSettings.cs:14-49`.

```json
{
    "Logging": {
        "G4Logger": {
            "OutputDirectory": "./logs",
            "AddConsole": true,
            "AddDebug": false
        },
        "LogLevel": {
            "Default": "Information",
            "G4.Api": "Debug"
        }
    }
}
```

The constructor does not read `Type` or `EventId` from the file. Set those in code or through `AddG4Logger(settings => ...)`.

`G4Logger.Instance` reads `Logging:G4Logger:AddConsole` and `Logging:G4Logger:AddDebug` and adds a console or debug logger beside the G4 logger when they are true. If building the factory fails, `Instance` is `null`. Source: `G4Logger.cs:393-432`.

## Limits

- Log files are not rotated and have no size limit. A file stays open for the life of the process and is named by the UTC day it was opened.
- The `Xml` type is not implemented.
- Scopes are not supported. `BeginScope` returns nothing (`G4Logger.cs:91`).
